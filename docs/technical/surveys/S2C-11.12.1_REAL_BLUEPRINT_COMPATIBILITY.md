## 7. Representative evidence

### CubeTopology / `LargeBlockArmorSlope2Base`

Exact vanilla definition in `Data/CubeBlocks/CubeBlocks_Armor.sbc`: Large, Size 1×1×1, `BlockTopology` Cube, `CubeTopology` Slope2Base, zero ModelOffset, no primary `Model`, `Sides` plate MWMs. This is the same Sides-driven armor class as the already-qualified Box / Slope / Corner / InvCorner constructions. Packaged leftover metadata already lists `Slope2Base` as residual automatable with `missing_construction`. Placement Size is already supported. The blocker is geometry-build, not source-resolution.

### Round CubeTopology / `LargeBlockArmorRoundSlope`

Same file and same Cube/Sides pattern, token `RoundSlope`, with curved plate MWMs (`SlopeRoundPlate.mwm`). Still CubeTopology, but the visible solid is not a planar cut of a cube.

### Definition parse / `LadderShaft`

`Data/CubeBlocks/CubeBlocks_Interiors.sbc`: TriangleMesh, `Model` `Models\Cubes\large\LadderShaft.mwm`, Size and ModelOffset serialized as child `X/Y/Z` rather than attributes. Targeted lookup currently requires Size attributes. If that one serialization form were accepted, this identity would be an ordinary Large Grid TriangleMesh candidate. Not implemented here.

### Definition parse / duplicate `BlockTopology`

`LargeBlockInsetWall`, `LargeBlockConsoleModule`, and `LargeBlockSciFiWall` each write `<BlockTopology>TriangleMesh</BlockTopology>` twice and have one primary Model. Lookup requires exactly one `BlockTopology`. The geometry class is already TriangleMesh. Not implemented here.

### Interior wall / `StandaloneBox`

`LargeBlockInteriorWall` omits `BlockTopology` and uses `CubeDefinition/CubeTopology` `StandaloneBox` plus Sides. Survey classification treats that as CubeTopology after read-only source inspection. Production lookup still marks the definition unusable.

### Empty subtype defaults

Gravity generator, oxygen tank, and O2/H2 generator use empty `SubtypeName` plus a concrete `MyObjectBuilder_*` type. The production parser correctly refuses to invent a subtype. Survey records the pair and does not map it to a default vanilla SubtypeId.

## 8. Generic-solvability assessment

| Cause | Solvability | Evidence |
| --- | --- | --- |
| `CUBETOPOLOGY_NOT_SUPPORTED` | `LIKELY_EXISTING_ARCHITECTURE_EXTENSION` for planar tokens; curved tokens need a broader primitive | Qualified native constructions already exist for Box, Slope, Corner, InvCorner. Slope2Base is already leftover automatable. HalfBox, Slope2Tip, SlopedCorner*, SlopeTransition*, HalfSlope*, StandaloneBox are additional planar/slab tokens on the same Sides + CubeTopology path. RoundSlope / RoundCorner are still CubeTopology but are curved; they are not “just another planar cut.” This is still the existing recipe/library path, not a new converter architecture. Support is not granted. |
| `DEFINITION_PARSE_UNSUPPORTED` | `LIKELY_EXISTING_ARCHITECTURE_EXTENSION` | Two bounded lookup patterns: Size/ModelOffset child triples, and duplicate identical `BlockTopology`. After that, the four identities look like ordinary TriangleMesh. Low instance count. |
| `EMPTY_SUBTYPE_OBJECT_BUILDER_DEFAULT` | `LIKELY_EXISTING_ARCHITECTURE_EXTENSION` / low value | A later parser rule could map empty `SubtypeName` + object-builder type to the unique empty-SubtypeId definition. Three instances. Must not invent identity casually. |

Causes that would have been `REQUIRES_NEW_ARCHITECTURE` (definition Subparts, mechanical/animation composites) did not appear in Salvador’s unresolved set. Many functional blocks on this ship already resolve as static TriangleMesh without definition-level Subparts.

## 9. Architecture implications

The post-11.11.1 pipeline already reconstructs a large vanilla functional-block majority when official SDK FBX exists and the definition is a single-primary-model Large Grid TriangleMesh. On Salvador that is 153 unique runtime identities and 506 instances, plus 4 packaged identities.

The remaining gap is not “functional blocks in general.” It is CubeTopology armor beyond the packaged eight, especially the 2×1 slope family.

CubeTopology should not be treated as one primitive. Evidence supports this split:

- **Likely another procedural primitive** (planar / slab / 2-step slope / sloped-corner family): 417 of 493 CubeTopology instances (Slope2Base 180 + Slope2Tip 74 + Half* + SlopedCorner* + SlopeTransition* + StandaloneBox).
- **Broader procedural geometry** (curved): RoundSlope 44 + RoundCorner 32 = 76 instances.

Subparts, MWM-only, OBJ, Small Grid, and multi-grid are not the next Salvador gap.

Packaged catalog remains 9 entries. Runtime binds remain transient. CubeTopology, Small Grid, and OBJ were not activated.

## 10. Recommended next decision

If the human later authorizes exactly one implementation unit, evidence points at **CubeTopology native constructions**, starting with the already-recorded leftover `Slope2Base` / `Slope2Tip` family and the other planar tokens that share the existing Sides-driven armor model.

That one cause is 493 instances, 19 identities, 39.85% of Salvador blocks, and 96.29% of unresolved instances. Hypothetically solving it raises supported coverage from 58.61% to 98.46% on this ship. That figure is classification math only.

This survey does **not** create or start that unit. Next executable unit remains none.

## 11. Residual unknowns

- Hypothetical coverage assumes every instance of a solved cause would become a correct CAD solid. Round* tokens may need more than a planar cut.
- Prefab wrap is survey intake. Production still parses ShipBlueprint only.
- Empty-subtype defaults were not mapped to vanilla SubtypeIds.
- InteriorWall `StandaloneBox` is CubeTopology/Sides, not the four qualified constructions.
- Salvador has no definition-level Subparts in the unresolved set; other ships may.
- No second ship was fully classified.
- No Salvador SolidWorks assembly was run.
- Salvador cell extents are Min-cell span, not Size occupancy, because production parse of the wrap fails on empty `SubtypeName`.
- Operator game/SDK env must not leak into ordinary tests; discovery tests read configured roots when present.
